# 架构说明

```text
SealDice 指令
  -> 统一路由与配置化文案
  -> 游戏引擎 / 房间状态机
  -> 扩展 KV：档案、钱包、房间、统计
  -> POST /api/render（仅排版数据）
  -> 渲染器短期缓存 PNG
  -> CQ:image 包裹的短 URL 回复
  -> （可选）官方 QQ keyboard.content.rows 指令按钮
```

## 官方Bot按钮

插件通过 `seal.replyToSenderWithKeyboard` 传递与官方协议兼容的键盘 JSON。按钮统一使用 `action.type=2` 和 `.yan ...` 指令，点击后重新进入普通指令路由；不携带 OpenID、Token 或房间内部身份数据。核心仅在适配器实现 `KeyboardReplySender` 时发送原生键盘，否则自动调用原有 `ReplyToSender`。图片富媒体消息不能直接挂键盘时，官方 QQ 适配器把控制按钮放到后续文字/Markdown消息，保持现有图片和分页行为。插件配置项“官方Bot图片分页提示”会通过短期标记把自定义提示传给核心，核心只在分页控制消息中替换该标记。

按钮生成器按 ViewModel 的 `kind` 和当前场景状态动态筛选操作，每条键盘最多5行、每行最多3个按钮；操作文本仍可手敲，按钮只是快捷入口。普通操作使用 `action.enter=true` 自动发送；德州看牌、爱赢一切手牌/公开、竞拍探索与私人情报、赏金私图使用 `action.enter=false`，点击后只填入用户输入框，用户可切换到绑定的官方 Bot 私聊再发送。插件通过 `aff.<game>.active.v1:<玩家>` 保存最近关联房间，私聊路由只读取该映射，不把群号、OpenID 或隐藏信息写入按钮载荷。`启用官方Bot按钮` 配置关闭后，所有适配器都回到原有回复流程。

## 恶魔轮盘赌

恶魔轮盘赌迁移自 `SpaceAdventure/星际迷航.js` V3.1。房间状态使用 `aff.room.v1:demon:<群>` 持久化，玩家档案中的 `demon` 保存评分、胜负、伤害、击杀和模式统计。模块保留原版 11 种模式、13 种道具和 8 种符文；`.恶魔 人机` 会自动运行骰娘 Bot，`.恶魔 开房/加入/开始` 支持多人轮流。盘面通过 `demonScene` 渲染为图片，弹仓在眼罩符文生效时隐藏；所有玩家的道具栏均为公开信息，不使用私聊状态。人机连续操作会保存到 `lastBotLogs`，当前回复集中展示 Bot 的道具、射击、符文和装填过程。

## 边界

- 海豹插件是权威状态源。扣费、好感、胜负和排行榜全部在扩展 KV 中完成。
- 身份入口先查询可选的 `SealOfficialQQIdentityBridge`。普通 `QQ:数字` 原样作为权威键；已验证绑定的官 Bot 用户与群映射到原 QQ/QQ群键。绑定前 OpenID 临时档案会在首次访问时合并，单人流程按更新时间择新，当前群房间同步替换房主、玩家和目标引用；未绑定或未安装桥接时仍按原身份独立运行。
- 新档案默认未注册，只有 `.yan 注册 <名字>` 成功后才会进入全局索引；旧档案按已有名字自动迁移，群名片不再覆盖登记名。
- `.yan 改名` 更新档案与排行榜索引，并同步当前上下文中的房间快照；其他群的旧房间会在玩家下次操作时同步。
- 渲染服务是无状态的纯排版器。它不能修改钱包，也不能决定胜负。
- ViewModel 除文字行外还支持 `meters`、`modules`、`tiles` 和 `rankings`，分别绘制状态条、模块摘要、详细数据块和排行榜专用行；`pokerTable`、`blackjackTable`、`dmdTable`、`farkleTable`、`scratchTicket`、`lotteryScene`、`deathDiceScene`、`loanScene`、`fishingScene` 与 `auctionScene` 负责各小游戏的专用场景。
- 图片服务不可用时，`replyView` 使用同一份 ViewModel 中的文字行生成回退消息，不需要维护第二套文案。
- 房间按 `游戏+群ID` 隔离；钓鱼、未刮票、双色球票据和借款账页按玩家 ID 隔离。双色球开奖号按日期全局共享。
- 双色球定时任务每日18:00只调用 `ensureLotteryDraw` 写入开奖号码和最近60期索引，不创建临时消息上下文，也不调用回复API。购票、状态和兑奖路径均可惰性补开奖，覆盖海豹在开奖时刻停机的情况；票据的开奖时间和下一期开奖时间共同定义兑奖窗口。
- 借款统一在 `loadProfile/saveProfile` 的迁移与保存边界执行先借先还。每笔债务独立保存好感损失，自动结算后可准确恢复该笔损失的一半，不依赖收入来源。
- 钓鱼图鉴只以安全结算时的 `haul` 为数据源；断线会先清空鱼篓，因此不会污染鱼种次数、大小极值或全局最大/最小鱼。三个水域的四档鱼池合计 96 种，旧版 48 种名称保持不变并继续兼容旧档案。每种鱼使用稳定的 `fish-001` 至 `fish-096` 资产编号，渲染器按需加载 6 张 4×4 图集并裁切当前物种；图集缺失时回退矢量鱼影。
- 竞拍图鉴只以正式玩家成交后的最终 `result.items` 为数据源。96种资产定义持久包含类别、稀有度、价格与固定 `width/height/sizeLabel`；每局只生成真伪、状态、矩形 `shape` 与 `gridX/gridY`。图鉴 ViewModel 额外汇总 `sizeHints`，让未解锁档案也能按尺寸看到候选货品。

## 德州规则实现

- 从 52 张标准牌中发牌。
- 对七张可用牌枚举全部 21 种五张组合，按牌型与踢脚逐项比较。
- 以每名玩家 `totalBet` 的不同层级构建主池和边池；弃牌玩家的投入计入池，但无获奖资格。
- 机器人只读取自己的底牌和公共牌，使用启发式强度下注，不透视其他底牌。

## 房间恢复

每次有效操作后立即序列化整个房间。海豹重启后，下一条指令会恢复局面。等待阶段退出或房主清理会退款；进行中房间不会因普通退出退款，以免重复结算。

`房间过期分钟` 默认 30。读取房间时如已过期：

- `waiting`：给所有已付费真人退款，然后清理。
- `playing`：清理但不退款。
- `finished`：可直接新建覆盖，或手动清理。

竞拍房是例外：每笔真人暗标都记录 `heldCoins`，因此 `playing` 房过期时会先调用竞拍专用退款，再清理房间。权威房间用 `lastRanking` 驱动 Bot 决策和成交判断，并把安全的 `rank/rankRound/rankHistory` 发给渲染器；其他座位 `ownBid` 永远为 0，也不会输出 `behavior`、私人估值或 Bot 性格字段。

竞拍房同时保存 `auctionRate`。当前比例为1游戏币兑换10000竞拍币；读取到缺失该字段或比例不同的旧房间时，先按原 `heldCoins` 退还已锁游戏币再清理，避免跨比例继续结算。

## 竞拍状态机

- 房间开始时按场地生成7至24件货品并装入12×10网格。货品形状由固定宽高生成完整笛卡尔矩形；摆放候选按相邻接触边数量排序，优先低接触位置。容器 `fogVersion=2`，旧形状房间会先退还 `heldCoins` 再清理。
- 房间共享 `publicExploredCells`，每个回合固定新增 4 个公共格；玩家分别持有 `exploredCells` 与 `exploredRound`，实现长期累计情报和每轮一次个人探索。`itemIntel` 只保留品类、状态、真伪等补充事实，不再用于泄露整件形状。Bot 另外持有私人评估、预算、风险、噪声、退出率、虚张声势、情绪偏移、盟友与竞争目标。
- 构造 ViewModel 时，未探索坐标只输出 `revealed=false`。只有物品全部占格已知时才进入 `items`；渲染器将矩形向内缩进3px后一次填充、裁切与描边，形成稳定物品间隙。`minimumEstimate` 只遍历至少一个已知格的货物，并以当前公开情报选择最保守乘数。
- 助手定义用 `kind/effect/triggerLabel` 分离探测、品类、统计与估价行为。开局被动在货柜生成后自动写入当前玩家的 `assistantReport`；逐轮升级通过 `assistantMilestones` 防止重复触发。估价报告只持久化取整后的 `low/high/confidence`，区间始终保留误差，不把 `saleValue` 原值放进 ViewModel；其他座位也不会获得查看者的报告。
- `.竞拍 出价` 覆盖当前暗标并同步 `heldCoins`。`solo` 房会同时写入 `confirmedRound` 并立即解析；`multiplayer` 房仍允许升降价，由 `.竞拍 确认` 写入 `confirmedRound`，全体有效真人确认后解析，未解析前 `.竞拍 撤回` 可清除确认状态。
- 每轮解析后把并列友好的价格名次写入玩家 `rank`，并按轮次写入五格 `rankHistory`；第6轮起的同价加赛继续更新第5格。ViewModel公开这些名次，但查看者以外的 `ownBid` 固定为0，具体金额不会随排名一起泄露。
- 第 1 至 4 轮使用 200%/160%/130%/110% 提前成交线，第 5 轮唯一最高价成交，平价时增加轮次。
- 结算先给所有落拍真人退回锁定资金，再给正式成交者发放出售收入、好感、图鉴和场地统计；游客和 Bot 只保留当前结算画面。

## 安全与资源限制

- 图片接口请求体上限 512 KiB。
- 标题、行和文案都有长度与行数限制。
- 背景只能从服务端固定映射中选择，客户端不能提交文件路径。竞拍暗标使用 `auction-yard.png`，成交开箱自动切换到 `auction-open.png`。
- 钱包和好感限制在安全整数范围内，刮刮奖金在生成和兑付时双重限制；双色球号码在指令入口和渲染入口分别校验范围，生死骰结算只执行一次全额余额替换。
